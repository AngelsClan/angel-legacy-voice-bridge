Angel Legacy Voice Bridge

Which add-on? This bridge speaks through SAPI 5 voices installed inside Windows XP. The separate Lion Voices, Snow Leopard Voices, Leopard Voices and Tiger Voices add-ons run their MacinTalk engines directly on the Windows computer with NVDA, without XP or this bridge. Angel Audio Keeper is separate again: it keeps sound outputs active but makes no speech. You can install these projects together when you need them.

Use old SAPI 5 voices that only run on 32-bit Windows XP as if they were installed in your modern NVDA. You keep a Windows XP virtual machine on your own computer with your licensed voices inside it. This add-on sends NVDA's text into that virtual machine. You can play bridge speech through XP, NVDA's selected output device, or both.

Everything stays on your computer. XP needs no internet connection, no network adapter and no copy of NVDA inside it. No voices are included; you supply your own licensed voices. By Angels Clan. This project was made with the help of AI.

Current status: please read first

This is development build 0.1.2-dev4 and the public release is on hold. A serious NVDA freeze was reported against version 0.1.1 and the exact cause is still unconfirmed. Real defects have been found and fixed since, but none has been proven to be the cause.

This build handles a measured few-byte SAPI bookmark offset after routed MacinTalk audio ends. It reports the bookmark after the real audio finishes and rejects larger unexplained gaps. NVDA-routed playback pause now reaches its audio player promptly even while the audio worker drains. XP-only pause still depends on the guest voice and sound output; check its audible timing on your setup.

If bridge speech fails and local eSpeak is restored, a short warning tone accompanies the spoken notice. The settings status keeps the last interruption reason even if the pipe reconnects.

So keep a dependable local synthesizer selected as your normal speech, leave the bridge disabled unless you are deliberately testing it, and do not try to reproduce a freeze if losing speech would leave you stranded. The fixes and diagnostics in this build are not a promise that the problem is gone.

How it works

There are two programs. The NVDA add-on runs on your modern Windows. A small console program, AngelLegacyVoiceBridge.exe, runs inside XP. They talk to each other over a virtual serial port that your virtualization software presents to Windows as a named pipe.

The add-on sends text to XP. By default, the voice plays through the virtual machine's own sound card. On the NVDA or Both route, the helper also sends rendered PCM over the serial link. Other XP sounds stay on XP. A successful connection alone does not prove that audio is playing.

Safety

Keep a working local voice selected until you have tested this build. NVDA+Shift+F11 immediately disables bridge speech, mirroring, automatic startup and retries, and answers "Bridge disabled. Local speech only." It keeps your current local synthesizer, or switches to eSpeak if the bridge itself was selected. You can reassign that shortcut under Input Gestures, in the Angel Legacy Voice Bridge category. NVDA+Control+S opens the ordinary synthesizer list.

This add-on is not available on secure login desktops, so do not rely on it as your only recovery speech. Installing or removing it needs an NVDA restart when it suits you; nothing restarts NVDA for you.

Installing: three steps

Step 1: add a virtual serial port to the VM

Shut Windows XP down normally first; virtual hardware must not be changed on a saved machine state. In VirtualBox, open Settings, Serial Ports, and on the Port 1 tab set: Enable Serial Port checked, Port Number COM1, I/O port 0x3F8, IRQ 4, Port Mode Host Pipe, Path/Address \\.\pipe\AngelLegacySpeech-XP. Leave "Connect to existing pipe" unchecked, so that VirtualBox creates the pipe and the add-on connects to it. Keep XP's network adapters disabled. Then start XP normally with its window visible.

The command-line equivalent, with the VM powered off, is VBoxManage modifyvm "Windows XP" --uart1 0x3F8 4 --uart-mode1 server "\\.\pipe\AngelLegacySpeech-XP" --uart-type1 16550A, substituting your own machine name.

The pipe name above is a generic default, not tied to one computer. You may choose another name as long as it begins with \\.\pipe\AngelLegacySpeech-, which is useful when you run more than one XP machine; type exactly the same name into the add-on. Only one program at a time can use a pipe.

Step 2: put the helper in XP and run it

Copy AngelLegacyVoiceBridge.exe from the release's XP Bridge folder into XP, for example into C:\AngelLegacyVoiceBridge. Guest Additions or an attached ISO are both convenient ways to copy it; neither is part of the speech connection, and you should not turn XP's networking on just to transfer a file.

Run it, for example with Windows+R and its full path. A console window opens and prints "Angel Legacy Voice Bridge 0.1.2-dev3. Waiting for the host. Ctrl+C exits." Leave it open and Alt+Tab away, or minimize it; Control+C closes it. When NVDA connects it reports the active route.

There is no driver to install, no service and no reboot. COM1 is the default; --com2, --com3 and --com4 are the only other arguments it accepts. Starting a second copy fails, because the first already owns the port. If it says "Cannot open configured COM port. Check VM serial settings and other bridge instances.", the port is missing or something else has it.

To start it after XP logs on, put a shortcut to the EXE in that XP user's Start Menu, Programs, Startup folder. Nothing creates that shortcut for you. The helper needs a logged-in user with a working audio session, which is exactly why it is an ordinary console program and not a Windows service.

Step 3: connect from NVDA and test

  1. Keep your normal local synthesizer selected, and make sure the XP helper is running.
  2. Open the NVDA menu, Preferences, Settings, and choose the Legacy Voice Bridge category.
  3. Check the name in Local bridge pipe, or press Detect running VM pipes and choose yours. If you kept the default name and exactly one bridge pipe is running under another name, the add-on adopts that one for you.
  4. Check Enable bridge now, or press Connect. Connection status should read something like "Connected; audio plays through XP; 14 voices; output: 22050 Hz, 16-bit, 1 channel(s)". The voice list fills in by itself; you do not need to press Refresh. The same button becomes Cancel connection while retrying, or Disconnect once connected.
  5. Choose a voice in Mirror/test voice and press Test speech through XP. The virtual machine should say "Angel Legacy Voice Bridge is ready. This sound comes from Windows XP."

Two ways to use it

Mirroring. Check "Mirror local NVDA speech to XP" and press OK. NVDA keeps speaking with your usual synthesizer and sends the same speech to XP as well, so two voices speak at once, slightly out of step. This is the safe way to try the bridge, because your normal speech never depends on it. Do not select NVDA's "No speech" synthesizer for this: mirroring accompanies a working local voice, it does not replace one.

As your synthesizer. Press NVDA+Control+S and choose Angel Legacy Voice Bridge, then set the voice, rate, pitch and volume in NVDA's ordinary Speech settings. Choose XP speakers, Send to NVDA, or Both in the Legacy Voice Bridge panel. Mirroring switches itself off while the bridge is your synthesizer, so you never hear the same words twice.

Save your configuration with NVDA+Control+C, or let NVDA save on exit, to keep these choices.

Changing sound quality while you read

With the bridge selected as your synthesizer, press NVDA+Control+Right Arrow until you reach XP output format in the settings ring, then NVDA+Control+Up or Down Arrow to change it. The next thing spoken uses the new setting; nothing reconnects or restarts, and audio already playing is not changed mid-word. The same option appears in ordinary Speech settings and shares one saved value with the Legacy Voice Bridge panel. When another synthesizer is selected and you are mirroring, change it in that panel instead.

The five choices are: "Voice default (recommended, best quality)"; "16 kHz, converted by XP (lower quality)"; "22.05 kHz, converted by XP unless the voice already uses it"; "44.1 kHz, converted by XP (can sound harsher)"; and "48 kHz, converted by XP (can sound harsher)". All bridge speech is 16-bit mono.

Voice default usually sounds best. A fixed rate makes XP's SAPI convert the voice's own output: measured on XP, converting the 22.05 kHz Mac voices to 44.1 or 48 kHz added false high frequencies only 21 to 27 dB below the voice itself, which sounds harsh or metallic. A higher rate cannot add detail an old voice never had, and no setting here repairs a poor virtual audio driver. A low bridge volume, such as 20, also costs real detail: prefer a higher bridge volume and turn the sound down elsewhere.

Every setting

Enable bridge now
The master switch for this session. Checking it connects and discovers voices; unchecking it stops bridge speech, mirroring and retries at once. Off by default.
Connect automatically when NVDA starts
Reconnect at the next NVDA start if the master switch is on. It does not boot XP or start the helper. Turning it off does not stop speech that is running now. Off by default.
Local bridge pipe
The exact pipe name your VM creates. No IP address and no guest password are involved. Switch to a local synthesizer before changing it.
Detect running VM pipes
Lists the bridge pipes that exist right now so you can choose one. It never starts, changes or inspects a virtual machine, and it can only find a pipe that is already configured.
Mirror local NVDA speech to XP
Send your speech to XP as well as to your normal synthesizer. Turning it off cancels mirrored speech immediately. The two voices can overlap and drift apart in timing. Off by default.
Where XP bridge speech plays
XP speakers (default), Send to NVDA, or Both XP and NVDA. This choice applies to bridge speech and the Test button. NVDA and Both need the matching updated XP helper. Other XP sounds remain on XP's sound card.
Mirror/test voice
Which XP voice mirroring and the Test button use, saved by its SAPI token ID so that it survives changes in list order.
Mirror/test rate (0–100)
50 by default, which is SAPI's normal speed. Engines interpret speed differently.
Mirror/test volume (0–100)
100 by default, and independent of the Windows and VM mixers. Zero silences most voices, but not all of them.
Set XP playback mixer to 100% when adjusting bridge volume
Optional, off by default. Asks XP to put its preferred output's master and Wave levels at maximum when you connect, test, apply or change the bridge volume. Bridge volume still controls the speech. It raises other XP sounds too, never unmutes anything, does not touch recording levels or your host's volume, and does not put the old levels back when you turn it off. The status line reports whether XP supported it fully, partly or not at all.
XP output format
The five choices described above. Apply affects later speech; Test uses the current choice. The status line shows the format SAPI actually reported once speech starts. An unsupported engine or device format can fail and trigger fallback.
Restore local eSpeak if bridge speech disconnects
Bring local speech back after a failure is detected, announcing "Legacy bridge unavailable. Switched to local eSpeak." On by default. Detection takes a few seconds; it is not instant.
Automatically return to the bridge after recovery
Off by default. See "When the voice fails" below for exactly what it does and how to turn it on.
Write text-free diagnostics log
On by default while the release is on hold. Records timings, queue counts and error numbers, never speech text or window titles, in angelLegacyVoiceBridge-diagnostics.log in NVDA's configuration folder. Takes effect immediately after OK or Apply, with no restart. If you turn it off before anything is written, no log file is created at all. Existing log files are never deleted for you.
Connection status
Read-only. Reports the connection, the number of voices found, the audio format XP reported, and the XP mixer result when that option is on.
Connect, Cancel connection, Disconnect
One button that follows the state. Connect applies the pipe name immediately and starts retrying. Cancel connection stops a connection attempt; Disconnect ends an established one. Both stop mirroring, automatic startup and retries, keeping local speech or selecting eSpeak if the bridge was your synthesizer. Press Connect again to reconnect.
Refresh voices and status
Update what is displayed. It is a convenience: the list already updates by itself.
Test speech through XP
Speak one fixed sentence using the mirror/test voice, rate and volume. Use it while a local synthesizer is selected. Mirroring pauses during the test so that settings announcements do not pile up behind it.
Stop test speech
Available only while test speech is playing or queued. It cancels the test, not the bridge, and mirroring may resume afterwards. It never mutes local NVDA. To stop everything, use Disconnect or NVDA+Shift+F11.
About
A short summary of what the add-on does, where the audio comes from, and how recovery works.

Enable, Mirror, Connect, Test and Disconnect act immediately, even if you then close the dialog with Cancel. Everything else applies on Apply or OK. Save your NVDA configuration to keep your choices.

The bridge synthesizer's own voice, rate, pitch and volume are separate from the mirror/test controls. Pitch runs 0 to 100 and maps to SAPI's XML pitch of -10 to +10; not every legacy engine honours pitch or spelling identically. Use one pipe across all your NVDA profiles for now, as switching transports automatically when a profile changes has not been qualified.

Installing new voices in XP

You do not have to restart the helper or reconnect. NVDA asks XP to re-examine its SAPI 5 registrations about every five seconds while speech is idle, and new voices appear in the list on their own; continuous reading defers the scan to the next idle gap. A voice installer may still ask XP to reboot for its own reasons, and only fully registered voices are offered.

A scan XP could not finish is not used at all: the previous list is kept and the next attempt waits an extra 25 seconds. If a scan gets no answer within four seconds while the connection otherwise looks alive, scanning is switched off until you reconnect; your voices keep working, and Disconnect followed by Connect resumes scanning. A helper run tracks up to 128 different voices, and if XP ever reports more than 128 at once the list is left unchanged rather than truncated.

Voice positions stay bound to the same voice for the helper's lifetime, including across removals, so queued speech never switches to a different voice behind your back. Removing the voice you are using triggers the normal failure and fallback path. Replacing the engine behind an existing voice is not the same as adding a voice: restart the helper after an engine upgrade if its installer asks for it.

When the voice fails

If the bridge is your synthesizer and the connection or the voice engine fails, NVDA does not go silent. "Restore local eSpeak if bridge speech disconnects" is on by default, and once the failure is detected NVDA says "Legacy bridge unavailable. Switched to local eSpeak." In mirror mode your local voice was speaking all along. Speech that was queued when the failure happened is discarded rather than replayed later.

By default you decide for yourself when to go back to the bridge.

Turning on automatic return

Automatic return is off by default. Turn it on either by checking "Automatically return to the bridge after recovery" in the settings and pressing OK, or with the command "Turn automatic return to the bridge after recovery on or off". That command has no key until you assign one in NVDA menu, Preferences, Input gestures, in the Angel Legacy Voice Bridge category. It announces "Automatic return to the bridge on" or "off", and turning it off also cancels a return that was pending. "Restore local eSpeak if bridge speech disconnects" must be on as well, since automatic return only ever follows that automatic fallback.

What automatic return actually does

It does not trust appearances: a pipe that reconnects, or a voice that still appears in the list, proves nothing, because a crashed engine can leave both looking healthy. Instead, while eSpeak speaks normally, the add-on sends a short fixed check phrase to the original voice. The updated XP helper captures and discards the sound on every route. A real final bookmark and non-silent captured audio are both required before returning.

  • The first check comes after 5 seconds and the wait then doubles, up to one minute. A single check that has not produced its bookmark within 15 seconds counts as a failure.
  • Checks stop after 12 attempts or 15 minutes, and NVDA says "Bridge voice did not recover. Staying on eSpeak."
  • When a check succeeds, your bridge voice, rate, volume and pitch are restored and NVDA says "Bridge voice recovered." through that voice.
  • If eSpeak is in the middle of a sentence when a check succeeds, the return waits up to 8 seconds for it to finish before interrupting.
  • At most three automatic returns happen in ten minutes, and each recent return lengthens the first wait: 5, then 10, then 20 seconds. After that NVDA says "Bridge failed repeatedly. Staying on eSpeak." and leaves the choice to you.
  • Changing synthesizer or local voice yourself, switching NVDA configuration profile, disabling the bridge or turning the option off all cancel a pending return. A missing original voice keeps local speech until that voice comes back. A pending return is not remembered across an NVDA restart.

Will you hear the check phrase? No. The updated helper captures and discards it without using XP speakers or NVDA's output device. An older helper cannot run a silent check, so automatic return stops and leaves eSpeak selected. Volume zero is still not a reliable mute for ordinary XP speech; use Disconnect or NVDA+Shift+F11 to stop bridge speech.

A successful check proves the engine rendered that one phrase. It cannot promise that the next paragraph will not fail.

Timing and limits

The worker retries a missing connection about once a second. A live session that stops replying is treated as failed after about four seconds, an unacknowledged packet after about four seconds even if heartbeats still arrive, and XP discards old speech after about six seconds without host contact. An utterance that never finishes is abandoned after 120 seconds plus half a second per character, not counting paused time. Selecting or restoring the bridge synthesizer allows a bounded two-second handshake wait; ordinary speech never waits for transport input or output. Operating-system and virtual-machine stalls can stretch all of these. They are safety limits, not promised response times.

Limits per utterance are 16,000 characters and 256 sequence items, with up to 64 utterances queued; larger requests fail cleanly instead of growing without bound. Small serial packets are assembled into one SAPI utterance before it speaks, without inserting prosody changes at packet boundaries, and bookmarks report position. Natural punctuation, requested breaks, separate NVDA utterances and VM scheduling can still cause pauses; zero latency is not promised. Mirroring follows NVDA's queued speech rather than reproducing its interruption timing exactly.

Privacy and compatibility

Your text goes into XP and its voice engine on purpose; that is the point. The local pipe is not encrypted and is not a security boundary against software already running on your computer as you, so trust the virtual machine and anything else using that pipe. This project's own logs never contain speech text, window titles, document contents or credentials; NVDA's own log settings and other add-ons may behave differently. There is no account, telemetry, online voice service or automatic updater, and nothing is uploaded.

The diagnostics log holds timings, counters, error numbers, code locations and, when speech fails, a "text shape": counts of digits, letters, spaces, punctuation, non-ASCII characters, double brackets, words and the longest word's length, never the words themselves. It is written on a separate thread with a bounded queue, so a slow disk drops records instead of delaying speech. The current log and two rotated copies come to roughly 3 MiB. The XP helper keeps a similar text-free file, bridge-sapi-errors.log, beside its own executable, which is emptied when it reaches 1 MiB. A native crash, an abrupt process kill or a full disk can still stop evidence from being recorded: this is a diagnostic aid, not a guaranteed crash recorder, and it cannot rescue speech while NVDA itself is hung.

Tested here: Windows XP 5.1.2600 under VirtualBox 7.2.18 with Microsoft Sam, AT&T DTNV 1.4 Mike16 and Crystal16, and 26 Panthera Classic Mac and Alex voices. The exact service pack was not recorded, and SP1, SP2 and SP3 have not each been separately qualified. VirtualBox is the only platform tested. Contributions that add or qualify other hypervisors and emulators, such as VMware, QEMU, Hyper-V, 86Box or PCem, are very welcome: see README.md, and open a pull request.

No SAPI 4 engines, network transport, system-wide SAPI 5 registration on the modern Windows host, or Windows service are included. The optional NVDA and Both routes do carry rendered audio back to NVDA's selected output device. An English-only voice still cannot pronounce every language or emoji; the bridge does not strip non-English text, because voices that support it must still receive it. Use licensed voices only.

Troubleshooting

No voices, or it will not connect. Check that the helper console is still open in XP, that COM1 exists in XP's Device Manager, that the pipe name matches exactly, and that no other copy of the helper or a test script already owns the pipe. XP's own Speech control panel confirms whether the voices work inside XP at all. The helper console and NVDA's log, under Tools, View log, both report what went wrong.

NVDA says "Connect and test the XP helper in Legacy Voice Bridge settings first." You selected the bridge as your synthesizer before it had a working connection and a voice list. Connect and run the test first, then select the synthesizer.

Connected, but silent. Check Where XP bridge speech plays. On XP speakers, check XP's own sound device, volume and virtual machine audio output. On Send to NVDA, check NVDA's selected output device and the connection status for an unsupported route. Both routes need a working SAPI 5 voice inside XP.

Silent for a moment right after switching to a voice, then fine. That is the voice engine starting up, not the bridge. It was seen with the Mac Alex voice packs, whose engine sometimes answered its very first utterance with a single silent frame and no error; those packs now render such an utterance a second time.

Harsh or metallic. Set XP output format to Voice default. The format is shared by every bridge voice, so if one voice prefers another setting, change it from the synthesizer settings ring as you switch voices.

Slow or stuck. Select a local synthesizer, stop any test speech, close the helper in XP with Control+C, start it again and press Connect. Virtual machine load, the VM's audio driver and slow legacy engines all affect responsiveness. Never turn XP's networking on as a workaround, and never run the developer integration tests while the bridge is your only speech.

Running XP without a visible window. At the VM's next normal start, use VirtualBox's "Start with detachable GUI", then Machine, Detach GUI to hide it; VirtualBox Manager, Show brings it back without rebooting XP. Minimize an already-running ordinary window instead of forcing a power cycle. XP still needs a logged-in user, the helper and working audio, and detached or headless audio has not been qualified here.

Maintenance without navigating NVDA. The source package's tools/disable_bridge.py --pid NUMBER sends a local disable-only signal to a running NVDA and waits for the worker to release the pipe. It cannot send speech, execute commands, restart NVDA or reach another computer. See OPERATIONS.md for that and for Guest Additions commands.

Removing it

Select a local synthesizer, turn off mirroring and automatic connection, remove the add-on in NVDA and restart NVDA when convenient. In XP, press Control+C in the helper console and delete its folder. Optionally, with the VM powered off, disable the serial port again. Removing this project never requires deleting your virtual machine or your voices.
