Angel Legacy Voice Bridge 0.1.2-dev2 — diagnostic development build

Release hold: an NVDA freeze with loss of speech remains unresolved. Keep reliable local speech selected and bridge operation disabled. This build is not a verified cure; do not reproduce the issue if losing speech would leave you without assistance.

Text-free diagnostics run even with the bridge disabled. The NVDA configuration directory contains angelLegacyVoiceBridge-diagnostics.log and up to two rotated copies (about 3 MiB total). Records include timing, queue counts and stalled code locations, not spoken text, window titles or credentials. When bridge speech fails, a text shape record adds only counts (digits, letters, punctuation, non-ASCII characters, double brackets, words), never the words themselves. Disk writes run separately and drop excess records rather than blocking speech. A hard native hang or process termination may still prevent capture. Logs are not uploaded.

Angels Clan. Use licensed SAPI 5 voices installed in an offline, 32-bit Windows XP virtual machine with modern Windows NVDA. XP speaks through its own virtual sound card. Neither internet access nor NVDA inside XP is required. Voice engines are not included.

Safety first

Keep a working local voice until you have tested this beta. NVDA+Shift+F11 disables speech, mirroring, retries and automatic startup. It keeps your current local synthesizer, or switches to eSpeak if the bridge was selected. You can reassign that shortcut under Input Gestures. NVDA+Control+S opens normal synthesizer selection.

This add-on is not available on secure login desktops. Do not use it as your only recovery speech. Installing or removing it requires an NVDA restart when convenient; the build never restarts NVDA automatically.

Two parts to install

The current XP helper fixes a reproduced fallback after voice reinstallation: it refreshes stale voice registrations and retries once only for SAPI's registry-key-deleted rejection. This specific repair works with the existing protocol-2 add-on and needs only a helper replacement, not an XP reboot or NVDA restart. Optional add-on error-detail improvements take effect after a safe NVDA restart. The helper also keeps a bounded, text-free bridge-sapi-errors.log beside its executable. This is not a claim that the separate reported freeze is fixed.

  1. Copy the release's XP Bridge folder to XP. The console program is AngelLegacyVoiceBridge.exe; double-click it after configuring the virtual serial port below. Leave it open and Alt+Tab away. Control+C exits.
  2. Development packages are not automatically installed. Only arrange installation and an NVDA restart at a safe time with reliable recovery speech. Do not install the add-on in XP. This update also replaces the XP helper: stop the old helper, replace its executable, then start it again. XP does not need to reboot.

The helper now polls actual speech completion without blocking, to recover missing completion events after skipped text. It also reports asynchronous voice-engine failures. This does not teach an English-only voice to read other languages and does not establish that the reported intermittent silence is fixed. Diagnostics include numeric voice slot, text length, format, rate and volume, but never speech text. Some legacy engines remain audible at volume zero; Disconnect or Disable bridge now stops bridge speech.

VirtualBox setup

Shut XP down normally before editing virtual hardware. In VirtualBox Settings, Serial Ports, enable port 1: COM1, I/O 0x3F8, IRQ 4, Host Pipe. Set the path to \\.\pipe\AngelLegacySpeech-XP. Leave “Connect to existing pipe” unchecked: VirtualBox creates the pipe. Keep XP network adapters disabled. Start XP with its visible window.

The default is generic, not tied to one VM. Choose another name beginning \\.\pipe\AngelLegacySpeech- if needed; enter exactly the same name in the add-on. With the default selected, a single matching running pipe is detected automatically. Detect running VM pipes lets you choose among multiple VMs. It does not configure or start a VM. Do not run two bridge clients on one pipe. COM1 is the helper default; --com2, --com3 or --com4 select another deliberately configured port.

Guest Additions are not required for speech. They can help copy the helper; an attached ISO is another offline transfer method. Choose your preferred sound output in XP and the hypervisor/host mixer. NVDA's audio-device setting does not route XP audio.

VMware: experimental, not currently supported

Not runtime-tested here. Power off the VM, add a serial port using a named pipe, set this end to server and the other end to application, connect at power on, and use the same local pipe path in the add-on. Match the helper's COM option. “Yield CPU on poll” may help if provided by your Workstation version. Keep networking off. Check the hypervisor's instructions for your version.

Connect and choose speech

  1. Keep your normal local synthesizer selected. Start the XP helper.
  2. In NVDA Preferences, Settings, open Legacy Voice Bridge.
  3. Confirm or detect the pipe, then check Enable bridge now or choose Connect. Voices and connection status update automatically. The same button changes to Cancel connection during retries or Disconnect when connected. Disconnect stops retries too.
  4. Select a Mirror/test voice and choose Test speech through XP. You should hear a short sentence from the VM.
  5. For both voices, enable Mirror local NVDA speech to XP, and Apply/OK. Keep a real local voice selected, not No speech.
  6. For XP-only NVDA speech, use NVDA+Control+S to select Angel Legacy Voice Bridge (audio through XP). Then choose the voice/rate/pitch/volume in ordinary NVDA speech settings. Mirroring does not duplicate the bridge itself.
  7. Save NVDA settings with NVDA+Control+C or the normal save-on-exit option.

Every setting

With the bridge synthesizer selected, use NVDA+Control+Left/Right Arrow to select XP output format in the synthesizer settings ring, then NVDA+Control+Up/Down Arrow to change it. The next dispatched utterance uses the change without reconnecting or restarting XP; speech already playing is unchanged. Save NVDA configuration to retain the choice. The same option is in normal Speech settings and shares the bridge panel's saved value. In mirror mode with another synth selected, use the bridge panel instead.

Enable bridge now
Master switch for current use. Checking connects and discovers voices. Unchecking disables speech, mirroring and retries immediately.
Connect automatically when NVDA starts
Start retries on next launch if the master switch is enabled. Does not boot XP or start its helper. Turning it off alone does not stop current speech. Saved mirror mode or selecting the bridge synth also needs a connection.
Detect running VM pipes
Find configured local pipes without changing the VM or its networking. Choose a VM if several match.
Local bridge pipe
The local named pipe configured in the VM. No IP address or guest password is needed. Switch to a local synthesizer before changing this field.
Mirror local NVDA speech to XP
Hear XP alongside your existing voice. Turning it off immediately cancels mirrored speech. The voices may overlap and have different timing. Off by default.
Mirror/test voice
Voice discovered from XP, saved by stable SAPI token ID. The updated helper scans about every five seconds while idle, detecting new/removed SAPI5 voices without a restart. Continuous reading defers scanning.
Mirror/test rate
0–100, with 50 normal; mapped to SAPI -10 to +10. Per-engine speed differs.
Mirror/test volume
0–100. Zero silences most voices, but some legacy engines stay audible at volume zero. Windows and VM mixer volume also apply.
Set XP playback mixer to 100% when adjusting bridge volume
Off by default. When enabled, connection, Apply/Test and synth volume changes request XP master and Wave playback levels at 100%. Bridge volume still controls speech. This raises other XP sounds too, does not unmute or change host volume, and does not restore old levels when disabled. Status reports complete, partial or unavailable support.
XP output format
Voice default (recommended), or 16, 22.05, 44.1 or 48 kHz, 16-bit mono. Apply affects future utterances; Test uses the current choice. Status shows SAPI's reported format after speech starts. Higher rates cannot restore missing detail in an old voice or fix a VM audio driver. A fixed rate makes XP convert the voice's own output, which measurably adds harsh false high frequencies for the 22.05 kHz Mac voices at 44.1 or 48 kHz; choose Voice default for the best sound. A low bridge volume such as 20 also costs detail, so prefer a higher bridge volume and lower the volume elsewhere. Unsupported engine/device formats may fail and trigger fallback.
Use local eSpeak if the bridge synthesizer disconnects
Automatically restore local speech on a detected failure. Enabled by default. Recovery detection takes time; use the emergency shortcut if needed.
Automatically return to the bridge after recovery
Off by default. To turn it on, check this box and press OK, or use the command "Turn automatic return to the bridge after recovery on or off", which has no key until you assign one in Input gestures under Angel Legacy Voice Bridge; it announces the new state, and turning it off cancels a pending return. Restore local eSpeak must also be on. After automatic eSpeak fallback, restore the previous bridge voice, rate, volume and pitch only after a short check phrase, sent at volume zero, renders in the original voice. A reconnected pipe alone is not enough. Measured on XP: Microsoft Sam and the Panthera Mac voices are silent at volume zero, but AT&T Mike and Crystal stay at about 18% of normal loudness, so with them the check phrase is heard briefly. Checks start after 5 seconds, back off to once a minute, and stop after 12 attempts or 15 minutes with a spoken notice. Manual synth or local voice changes, profile switches, Disconnect, or turning this option off cancel pending return. Failed restoration stays local. Pending return is not saved across NVDA restarts.
Connect / Cancel connection / Disconnect
One state-aware button. Connect applies the pipe immediately and starts retries. Cancel connection and Disconnect stop speech, mirroring, startup and retries, keeping local speech or selecting eSpeak. Click Connect again to reconnect.
Refresh voices and status
Refresh displayed information that also updates automatically. Live scanning offers up to 128 distinct SAPI5 token IDs per helper run. It is not limited to Mike and Crystal; old helpers must be updated for live scanning.
Test speech through XP
Use the mirror/test controls for one synthetic phrase. Only available with a local synthesizer. Mirroring pauses during the test so settings announcements do not fill its queue.
Stop test speech
Enabled only while test speech is queued/active. Cancels the test. Configured mirroring may resume afterwards; use Disconnect or NVDA+Shift+F11 to stop everything.
About
Purpose, audio routing, recovery and help information.

Enable, Mirror, Connect, Test and Disconnect act immediately, even if you later cancel this dialog. Other settings apply on Apply/OK. Save NVDA configuration to retain choices. Update both the XP helper and this add-on for this same-version beta. Older protocol-2 helpers can speak but lack live scans and mixer control.

Normal bridge synthesizer voice settings are separate from mirror/test settings. Pitch 0–100 maps to -10 to +10 SAPI XML pitch. Use the same pipe across NVDA profiles in this beta; automatic profile-triggered transport switching is not qualified.

Disconnects and performance

Automatic return is limited to three returns in ten minutes; NVDA announces when it stops. After repeated failures, select the bridge manually once the issue is corrected. Incomplete voice scans preserve the last good catalog and retry later; unchanged scans use a short reply. A scan timeout on a responsive connection disables scanning until reconnect. The brief scan can delay newly queued speech; zero latency is not promised.

The worker retries about once per second. Missing replies normally trigger host fallback in about four seconds; XP normally clears old speech after six seconds without host contact. Operating-system and VM stalls can delay this. Selecting/restoring the bridge synthesizer allows at most a two-second initial handshake wait; normal speech and settings operations do not wait for transport I/O.

Disconnected or canceled speech is discarded, not replayed later. After falling back, NVDA stays on its local voice unless you enabled automatic return. Both fallback and automatic return must be enabled for that round trip. Completion timeout is 120 seconds plus half a second per text character, excluding paused time. Missing packet acknowledgements time out in about four seconds even if heartbeats arrive.

Small serial packets assemble one full utterance before SAPI speaks, without repeating voice-format tags at packet boundaries. SAPI bookmarks report positions. Natural punctuation, requested breaks, separate NVDA utterances and VM scheduling can still cause pauses. Mirroring follows queued speech, not exact local-synth priority timing. Zero latency and perfect pronunciation are not promised. Limits are 16,000 text characters/256 items per utterance and 64 queued utterances.

Privacy and compatibility

Text goes to XP and its SAPI voice engine. The local pipe is not encrypted and is not a boundary against hostile software already on your computer. Trust the VM and host applications. The add-on and helper do not log speech content; NVDA's own log settings and other add-ons may behave differently.

The helper was exercised on XP 5.1.2600 under VirtualBox 7.2.18 with Microsoft Sam, AT&T DTNV 1.4 Mike16 and Crystal16. The exact service pack was not confirmed. Separate XP SP1/SP2/SP3 and VMware qualification is still needed. NVDA 2026 APIs were checked and adapter logic tested; full interactive screen-reader and listening acceptance is still required. This is a beta.

No SAPI4-only engines, network transport, system-wide SAPI5 registration, audio streaming to NVDA's selected output, or Windows service is included. A console keeps audio in the logged-in XP user's session. Use licensed voices only.

Troubleshooting

New voices are detected without restarting the helper, during idle scans. An installer can still require its own reboot. SAPI4-only voices are unsupported. Removing the selected voice triggers normal fallback. Indexes remain stable; removed IDs are retained until helper exit, with a limit of 128 distinct IDs per run.

At XP's next normal start, choose VirtualBox Start with detachable GUI. Machine > Detach GUI hides it; VirtualBox Manager > Show brings it back without rebooting XP. Minimize an already-running ordinary GUI instead. XP still needs a logged-in user, helper and working audio. Visible mode was tested; detached/headless audio is not yet qualified.

Helper startup and maintenance

The suggested XP path is C:\AngelLegacyVoiceBridge\AngelLegacyVoiceBridge.exe. Windows+R and that path starts its console. Minimize or Alt+Tab away; Control+C exits. No desktop shortcut or autostart is installed. To start after logon, put a shortcut in that XP user's Programs > Startup folder. The NVDA settings panel configures pipe discovery, voice, format and recovery, not VirtualBox hardware.

The source package's tools/disable_bridge.py --pid NUMBER sends a local disable-only signal to an updated NVDA process and waits for the worker to release the pipe. It cannot execute commands, restart NVDA, or control another computer. It requires host Python 3, the intended NVDA process ID and the same local Windows session. See OPERATIONS.md for Guest Additions launch commands, safety boundaries and diagnostics.

No voices: check the running XP helper, COM number, exact pipe path and whether another test/client owns it. Connected but silent: test XP's normal sound and Speech control panel, then its output and mixer settings. Try a different installed voice. A transport test cannot prove speakers are audible.

Silent only for a moment after switching to a voice, then fine: the voice engine is starting up, not the bridge. The Mac Alex voice packs sometimes answered their first utterance with a single silent frame; those packs now render such an utterance again. Harsh or metallic sound: set XP output format to Voice default. Voices do not all prefer the same format, and the setting is shared by all bridge voices, so change it in the synthesizer settings ring when you switch to a voice that sounds better another way.

For a stuck engine restore local speech, close/reopen the helper, and reconnect. View lifecycle/errors in the XP console and NVDA Tools, View log. Do not enable XP networking as a workaround. Never run developer integration tests while relying on the bridge as your only speech.

Removal

The 0.1.1 bookmark fixes did not establish a cure for the reported freeze. Its third-party INFO progress records were filtered by normal NVDA logging. Development diagnostics use a separate bounded file, but are not an automatic recovery mechanism. Do not deliberately reproduce loss of speech on your primary screen reader.

Select local speech, disable mirroring/automatic connect, remove the add-on and restart NVDA when convenient. Close the XP helper with Control+C. Its folder can then be removed. Optionally disable the virtual serial port while the VM is powered off. Do not delete your VM or voice installations.

Engine-failure recovery update

The September 22 development add-on clears abandoned speech and indexes before falling back to local speech. The old version could select eSpeak but leave its speech queue blocked. Automatic return and disabling an active bridge also reset speech queues. Old announcements are discarded, not replayed. Numeric error snapshots and bridge-selected backlog labels improve diagnosis without recording speech text. A separate Pipe Organ engine failure was traced to the Mac voice pack, not the bridge: it sent text to Apple's engine in the wrong encoding, so non-English letters arrived as garbage. The voice pack is fixed and the result is being confirmed in normal use; this does not lift the release hold. Install the updated add-on only at a safe restart time. The existing updated XP helper need not be replaced again.
